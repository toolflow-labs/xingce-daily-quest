# Xingce Daily Quest

把行测练习从“坐着刷题”改造成连续 90 天的小游戏实验。

> 目标：未来 3 个月，每天选取一张行测试卷，提炼其中一种能力结构，并做成一个可玩的网页小游戏。

## 项目定位

这不是普通题库，也不追求把整张试卷机械搬到网页里。

每天重点完成三件事：

1. 从一张试卷中提取代表性题型；
2. 为题目设计一套有反馈、有节奏的游戏机制；
3. 记录当天的设计判断、可玩性和后续改进方向。

首个原型采用“赛博战斗答题”：答对攻击 Boss，连续答对提高伤害；答错或超时损失护盾；能量可以排除选项或延长时间。

## 试玩

打开仓库根目录的 `index.html`，或直接进入：

- `days/day-001/index.html`

项目使用原生 HTML、CSS、JavaScript，无需安装依赖。

本地运行：

```bash
python -m http.server 8000
```

然后访问：

```text
http://localhost:8000
```

后续每一天沿用 `days/day-xxx/` 目录，不拆出大量说明文档；项目规则、运行方式与进度统一维护在本 README 中。

## 每日制作流程

1. 选择当天试卷；
2. 判断最适合的玩法，而不是先套固定模板；
3. 只选足够支撑玩法的代表题目；
4. 完成可玩的最小版本；
5. 在 README 更新进度，并记录当天最有效的机制。

推荐每天至少保留以下信息：

```text
Day：
试卷类型：
游戏类型：
核心机制：
代表题型：
当天结论：
下一步：
```

## 内容原则

- 不在仓库中上传原始试卷 PDF；
- 公开版本优先使用改写、缩写或结构化后的代表题目；
- 项目用于个人学习、交互设计实验和技术练习；
- 第三方试题、品牌与资料的版权归原权利人所有。

## 技术方向

当前先使用原生 Web 技术快速迭代。随着玩法稳定，可以逐步尝试：

- Canvas / Phaser：更丰富的动画与碰撞反馈；
- 题目 JSON 标准：支持批量导入与复用；
- 错题复盘：记录答题过程，而不只记录结果；
- PWA：支持手机端离线练习；
- GitHub Pages：直接在线试玩每天的版本。

## Day 001 设计记录

**名称：** 上岸协议 001：认知核心

**玩法：** 驾驶“上岸号”对抗认知核心。

**有效机制：**

- 答对立即攻击，比单纯显示绿色对勾更有反馈；
- 连击与伤害绑定，鼓励持续专注；
- 排除选项和时间延长消耗同一种资源，产生轻量决策；
- 一局只保留 8 题，适合作为游戏原型，而不是完整模考。
